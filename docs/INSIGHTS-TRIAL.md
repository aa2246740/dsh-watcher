# Watcher 0.4.0-insights.1 试用

基线：DSH 0.1.2-rc.1；分支：feat/session-insights-rc1。只读，无云端，没有第二个模型。

## 装上和回滚

本地 clone 这个分支，执行 `npm install`、`npm run build`、`npm test`。在运行 dsh 的同一个环境执行 `dsh plugin --profile web remove dsh-watcher`，再 `dsh plugin --profile web add /绝对路径/dsh-watcher`。重启 DSH Host 并刷新页面。安装路径不能随意移动。

回滚：停止 Host，在插件源码目录切回 main，然后重新启动 DSH；main 自带旧版 lib 产物。不要对未保存的代码执行强制 reset。移除插件不会删除 DSH 会话。

## 看什么

会话标题的眼睛仍是原入口，不添加另一个直播条。面板上方展示“本轮 / 会话”的已报告 Token、模型累计时间、工具失败和接口重试；原工作路径保留供查证。完整历史不再在打开面板时自动补齐，按需点“载入完整路径”。

设置 → Watcher：默认扫描最近 30 个普通会话，可刷新最近 100 个；按 provider/model 展示用量、首响应、工具失败、接口重试，提供异常证据和提醒阈值。这是按需快照，不是持续订阅全部会话。当前会话投影实时更新。

规则初版只有三类：同参数与同结果的连续失败（达到 3 次）；运行中的模型内容静默（默认 30 秒，等待用户时暂停）；已收到可见推理片段的首末跨度偏长（默认 90 秒）。这些是提醒，不是确定的空转或成功率；不会自动停止任务。

## 覆盖和口径

统计来自 Host 的 watcherInsights 投影，折叠完整持久 Session 日志，不依赖浏览器当前加载窗口。fork 的继承前缀只恢复模型配置、不重复计费。动态 delta 的视图最多每 500ms 发布一次，settlement 立即发布。调用还没返回 usage 时明确显示未结算；缺失 usage 不计作零消耗。缓存输入与普通输入独立计算，推理 Token 不再额外加入总数。

初版不计入直接子代理、其他 Host、绕过 Session 的标题/压缩等辅助调用，也不提供账单、质量排行榜或自动模型推荐。设置页会明确显示未计入和读取失败的会话。模型计时取步骤边界，重试起点未知时不伪造耗时；可见推理首末跨度不是内部思考时间。

服务端投影不保存正文；重复失败仅保留 Host 侧指纹，界面传递来源 seq。推理正文仍只通过原会话证据浏览。阈值存当前浏览器，非 Host 全局配置。

## 试用验收

1. 正常跑一次多步骤任务，打开眼睛，看摘要是否比原工作日志更有助于判断。
2. 同一条失败调用出现三次时，查看规则证据；改动参数或成功结果应中断重复失败串。
3. 生成推理后流静默，时间不能继续被算成“可见推理输出”。
4. 运行结束后刷新，比较实时与 packed 历史推理记录。
5. 设置页检查分模型统计、读取覆盖数量和缺失数据说明；不要把正常结束视为任务验收通过。

CI 应构建并运行完整测试，成功后只回写此分支的源代码及 lib。构建不等同于完整官方 Host 端到端运行验证；请以具体测试记录为准。
